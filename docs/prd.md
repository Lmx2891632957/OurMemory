# 产品需求文档（PRD）

> 版本：v0.1（2026-11-03）· 状态：待评审
> 这份文档定义「做什么、不做什么、先后顺序」，不涉及具体实现。

## 1. 一句话定位

给两个人用的私密生活记录本：**拍一张照片，自动带上时间和地点，攒成一条可以回看的时间线。**

## 2. 目标用户与场景

| | 说明 |
|---|---|
| 用户 | 情侣两人（当前阶段：一人使用，另一人后续加入） |
| 核心场景 | 出去玩/吃饭/日常瞬间，随手拍一张，写一句话，记录「我们在哪、什么时候」 |
| 回看场景 | 翻时间线、按地点看「去过哪」、按日期找某天做了什么 |
| 非目标 | 不是社交平台：不发广场、不追求点赞数、不做推荐流 |

## 3. 产品原则

1. **本地优先**：没有网络也能记录、能看历史；云端只做同步，不做唯一数据源。
2. **记录成本最低**：从点「+」到发布完成 ≤ 3 步，≤ 15 秒。
3. **隐私默认**：数据默认只在本机；同步是显式开启的能力。
4. **中文友好**：地址、时间、文案都是中文习惯表达。

## 4. 当前状态（v1.1.1）

已完成：相机拍照、高德定位与逆地理、地图选点（含附近地点）、发布、信息流、点赞、删除、隐私合规、本地持久化。

这意味着**单机闭环已经跑通**，接下来是「把体验做厚」，而不是补地基。

## 5. 功能清单（MoSCoW）

### P0：下一版必须有（体验从"能用"到"好用"）

| 功能 | 价值 | 成本 | 验收标准 |
|---|---|---|---|
| 多图记录（最多 9 张） | 一次记录一张图太受限，九宫格是刚需 | 中 | 编辑页可加/删/排序，信息流按 1/2/3+ 张自适应排版 |
| 详情页 | 信息流卡片空间有限，长文+多图需要完整视图 | 低 | 点卡片进详情，可左右滑图、完整文字、地点地图小图 |
| 时间线按天分组 | 记录变多后找不到"那天" | 低 | 列表出现「今天/昨天/11月3日」分组头，滚动时吸顶 |

### P1：有了更好（下一阶段）

| 功能 | 价值 | 备注 |
|---|---|---|
| 相册视图（按月网格） | 快速回看照片 | 与时间线共用数据 |
| 地图回忆（按地点聚合） | "我们去过哪"是情侣 App 的灵魂 | 依赖地点数据质量 |
| 心情/标签 | 让时间线有情绪维度 | 先做预置 6~8 个，不做自定义 |
| 搜索（文字/地点） | 记录多了要能找 | Room FTS 或简单 LIKE |
| 导出/备份 | 换手机不丢数据 | 先做「导出 zip 到本地」 |

### P2：以后再说

评论互动（需要双人同步）、纪念日提醒、桌面小组件、多设备同步、上架发布。

### 明确不做（本期）

- 公开社交（关注/广场/推荐）
- 视频、滤镜、美颜
- 复杂账户体系（手机号/微信登录）——先本地身份，同步时再定
- **编辑已发布的记录**：发错了就删除重发，不做编辑态（用户明确要求，降低实现与同步复杂度）

## 6. 关键决策记录

| 决策 | 结论 | 理由 |
|---|---|---|
| 数据共享 | 先单机，**数据模型预留同步字段** | 双人同步需要后端+账号，周期长；先做好单机体验，后续换 Repository 实现即可 |
| 地图服务 | 高德（GCJ-02） | 国内可用、免 Google 服务、逆地理质量好 |
| 照片存储 | 应用私有目录，不传云 | 隐私 + 无需存储权限 |
| 同步冲突 | 预留 last-write-wins + 软删除 | 实现简单，情侣场景冲突少 |

## 7. 成功标准（个人使用视角）

- 从打开 App 到发布一条记录，**不超过 3 次点击 + 1 次输入**。
- 相册里任意一条记录，**2 次点击内能看到大图和地点**。
- 断网状态下，拍照、写文字、保存、浏览全部可用。

## 8. 需求变更流程

新想法先写进本文档的候选区，标注优先级和成本；**未进 P0 的需求不写代码**。
这是为了避免"边做边加"导致永远发不出可用版本。
